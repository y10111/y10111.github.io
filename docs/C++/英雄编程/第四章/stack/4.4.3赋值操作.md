## 本节概述：stack 的赋值操作

stack 的赋值操作在实际开发中**用得很少**，这节课的重点不在"怎么用"，而在于借它复习一下**面向对象里的运算符重载**——看看一个小小的等号背后，编译器到底帮我们做了什么。

## 基本用法

赋值就是用一个等号，把右边的栈赋给左边的栈：

```cpp
stack<int> stk1;
stack<int> stk2;

stk1 = stk2;   // 把 stk2 赋给 stk1
```

> [!WARNING]
> **又是"未定义的标识符"**
>
> 老规矩——如果报这个错，先检查有没有 `#include <stack>`。

> [!NOTE]
> 说实话，这个赋值在真正的开发里几乎用不到，因为栈本来就是"用完即走"的临时结构。了解它的底层实现，更多是为了复习运算符重载。

## 这个等号是怎么实现的

学过面向对象的同学应该会想：这个 `=` 会不会是一个**运算符重载**呢？我们来验证一下。

对 `stack` 按 F12 跳进定义，搜索 `operator=`——**发现并没有这个函数**（只有别的 operator）。

既然 stack 类里没有自己写 `operator=`，那就说明它采用的是**编译器默认生成的赋值运算符**。

## 默认赋值：逐成员调用

默认的赋值运算符做的事很朴素——**看这个类有几个成员，然后让每个成员各自调用自己的 `operator=`**。

那 stack 有几个成员？跳进源码（大约 144 行附近）会发现，stack 的代码非常短，**只有一个成员变量 `container`**：

```cpp
template <class T, class Container = deque<T>>
class stack {
protected:
    Container c;   // 就这一个成员
    // ...
};
```

这个 `container` 是什么？就是上一节我们看到的——**deque**。

所以 `stk1 = stk2` 实际发生的事就是：

```
   stk1 = stk2
      │
      │  默认赋值 → 逐成员赋值
      ▼
   stk1.c = stk2.c        （c 就是 deque）
      │
      │  deque 自己的 operator=
      ▼
   底层的 deque 完成真正的数据复制
```

也就是说，真正干活的是 deque 的赋值运算符。

## 验证：断点看调用堆栈

光看源码还不够，打断点实锤一下。

1. 对 deque 按 F12，搜 `operator=`——**这次是有的**。
2. 在 deque 的 `operator=` 里打一个断点。
3. 点击调试运行，程序停在断点处。
4. 看**调用堆栈**，双击上一层，会发现——原来这个等号最终**掉到了 deque 的 `operator=` 里**。

```
main
 └── stack<int>::operator=   ← 编译器默认生成的，逐成员赋值
      └── deque<int>::operator=   ← 真正干活的（断点停在这里）
```

这就验证了我们的推断：stack 自己没有赋值逻辑，全靠底层 deque。

> [!TIP]
> **这就是赋值重载的复习**
>
> - 类如果没写 `operator=`，编译器会自动生成一个默认的（逐成员赋值）
> - stack 就属于这种情况，它把活儿交给成员 `container`
> - 如果这里听着有点懵，建议回头复习一下 C++ 面向对象课程里的**运算符重载 → 赋值重载**那一节

## 本章小结

**用法很简单** — 一个等号 `stk1 = stk2` 即可，但实际开发中很少用到。

**stack 没有 operator=** — 搜源码会发现它没有自己实现赋值，用的是编译器默认生成的赋值运算符。

**默认赋值 = 逐成员赋值** — stack 只有一个成员 `container`（也就是 deque），所以等号最终变成 deque 的赋值。

**断点验证** — 在 deque 的 `operator=` 打断点，调用堆栈会显示从 stack 一路调到 deque。

**本质是复习运算符重载** — 这个例子串起了面向对象里的赋值重载知识。
