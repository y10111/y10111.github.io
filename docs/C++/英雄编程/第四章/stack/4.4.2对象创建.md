## 本节概述：stack 的对象创建

相比 vector 和 deque 的六种创建方式，stack 的创建要简单得多——它只有**两种**：默认构造和拷贝构造。本节顺带深挖一下 stack 的底层物理结构，看看它到底是怎么实现的。

## 两种创建方式总览

| 方式 | 语法 | 说明 |
|---|---|---|
| 1. 默认构造 | `stack<int> stk` | 空的栈 |
| 2. 拷贝构造 | `stack<int> stk(other)` | 复制另一个同类型 stack |

> 为什么这么少？因为 stack 是访问受限的容器，不能像 vector / deque 那样用初始化列表、迭代器区间、count 个值来批量初始化——它压根没有迭代器，数据只能一个一个 push 进去。

## 方式一：默认构造

最常用的一种，直接调用默认构造函数：

```cpp
stack<int> stk1;
```

> [!WARNING]
> **"未定义的标识符" 报错**
>
> 如果写了 `stack<int> stk1;` 编译器报错说"未定义的标识符"，别慌，原因只有一个——
> **没有引入头文件**。加上 `#include <stack>` 就好了。
>
> 这类"找不到标识符"的报错，几乎都是漏了头文件，一眼就能看出来。

## 方式二：拷贝构造

括号里传一个**同类型**的对象进来：

```cpp
stack<int> stk2(stk1);
```

> 函数签名：`stack(const stack& other)`
> 把 stk1 完整复制一份给 stk2，两个栈各自独立。

## 完整代码示例

```cpp
#include <iostream>
#include <stack>
using namespace std;

int main() {
    // 1. 默认构造
    stack<int> stk1;
    stk1.push(10);
    stk1.push(20);

    // 2. 拷贝构造
    stack<int> stk2(stk1);

    // 验证拷贝成功
    cout << "stk1 top: " << stk1.top() << endl;    // 20
    cout << "stk2 top: " << stk2.top() << endl;    // 20
    cout << "stk1 size: " << stk1.size() << endl;  // 2
    cout << "stk2 size: " << stk2.size() << endl;  // 2

    return 0;
}
```

运行结果：

```
stk1 top: 20
stk2 top: 20
stk1 size: 2
stk2 size: 2
```

## 深入底层：stack 的物理结构

代码太短，正好借这节课看看 stack 里面到底长什么样。

对 `stack` 按 F12 跳进定义，会看到一个**类模板**：

```cpp
template <class T, class Container = deque<T>>
class stack;
```

它有两个模板参数：

| 参数 | 含义 | 我们这个例子里的值 |
|---|---|---|
| 第一个 `T` | 元素类型 | `int` |
| 第二个 `Container` | 底层容器类型（有默认值） | `deque<int>` |

> [!TIP]
> **第二个参数不写会怎样？**
>
> 它有个**默认参数** `deque<T>`。我们平时写 `stack<int>` 只给了一个参数，第二个参数就自动取默认值。
>
> 也就是说——**stack 的底层竟然是个 deque（双端队列）**！

### 为什么底层用 deque

仔细想确实合理：deque 的功能比 stack 丰富得多，既能头插又能尾插。而 stack 只需要**把 deque 的头插功能禁掉**，只保留尾插尾删就行了。

```
        使用者看到的 stack
   ┌─────────────────────────┐
   │   push / pop / top      │   ← 只暴露这三个接口
   └────────────┬────────────┘
                │  内部只调用尾插尾删
   ┌────────────▼────────────┐
   │   deque<int>（双端队列）  │   ← 真正干活的底层容器
   │   头插  ← 被禁掉          │
   │   尾插  ← 保留            │
   └─────────────────────────┘
```

所以 stack 根本不需要自己从头实现一套存储结构，**直接复用 deque 的物理结构**，在外层套一个"只准尾插"的壳就行。

> [!NOTE]
> **这就是适配器（Adapter）思想**
>
> stack 本身不管理内存，它只是把已有的容器（默认 deque）包装一层，改一改接口。
> 这也解释了为什么 stack 没有迭代器——底层容器明明有，但 stack 故意不对外暴露。

## 本章小结

**只有两种创建方式** — 默认构造 `stack<int> stk` 和拷贝构造 `stack<int> stk(other)`，比 vector / deque 简单得多。

**报错先看头文件** — "未定义的标识符"基本都是漏了 `#include <stack>`。

**底层是 deque** — stack 是个类模板，第二个模板参数默认就是 `deque<T>`，所以我们平时写的 stack 底层其实是双端队列。

**复用而非重写** — deque 功能更全，stack 只需把头插禁掉、只留尾插尾删，直接复用它的物理结构即可。
