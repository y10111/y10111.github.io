## 本节概述：unordered_map 的数据查找

unordered_map 的查找用 `find` 函数，参数传的是 key，返回值是迭代器。找到就返回指向该键值对的迭代器，找不到就返回 `end()`。

## find 函数的用法

```cpp
#include <iostream>
#include <unordered_map>
using namespace std;

int main() {
    unordered_map<int, int> um = {
        pair<int, int>(1, 4),
        pair<int, int>(2, 80),
        pair<int, int>(3, 20),
        pair<int, int>(4, 17)
    };

    unordered_map<int, int>::iterator it = um.find(3);

    if (it != um.end()) {
        cout << "找到键值对：("
             << it->first << ", "
             << it->second << ")" << endl;
    } else {
        cout << "未找到" << endl;
    }

    return 0;
}
```

运行结果：

```
找到键值对：(3, 20)
```

## find 的底层流程

```mermaid
graph TD
    A[find(key)] --> B[计算 hash(key)]
    B --> C[找到对应的 bucket]
    C --> D[遍历桶内链表<br/>逐个比较 key]
    D --> E{找到相同 key 吗}
    E -->|是| F[返回指向该元素的迭代器]
    E -->|否| G[返回 end()]
```

## 判断是否找到的逻辑

| 返回值 | 含义 |
|---|---|
| 不等于 `um.end()` | 找到了，`it->first` 是 key，`it->second` 是 value |
| 等于 `um.end()` | 没找到，此时不能解引用 |

> [!WARNING]
> **找不到时不要解引用**
>
> 如果 `find` 返回 `end()`，说明没找到，这时候 `it->first` 或 `it->second` 是未定义行为，可能会崩溃。
>
> 一定要先判断 `it != um.end()`，再访问迭代器内容。

## 找到和找不到两种情况

```cpp
unordered_map<int, int> um = {
    pair<int, int>(1, 4),
    pair<int, int>(2, 80),
    pair<int, int>(3, 20),
    pair<int, int>(4, 17)
};

// 找到的情况
unordered_map<int, int>::iterator it = um.find(4);
if (it != um.end()) {
    cout << "找到：(" << it->first << ", " << it->second << ")" << endl;
} else {
    cout << "未找到 key=4" << endl;
}

// 找不到的情况
it = um.find(5);
if (it != um.end()) {
    cout << "找到：(" << it->first << ", " << it->second << ")" << endl;
} else {
    cout << "未找到 key=5" << endl;
}
```

运行结果：

```
找到：(4, 17)
未找到 key=5
```

## find 是按 key 查找，不是按 value

find 的参数是 key 的类型，它只根据 key 来查找，和 value 完全没关系。

```cpp
unordered_map<int, int> um = {
    pair<int, int>(1, 4),    // key=1, value=4
    pair<int, int>(2, 80),
    pair<int, int>(3, 20),
    pair<int, int>(4, 17)    // key=4, value=17
};

unordered_map<int, int>::iterator it = um.find(4);
// 找到的是 key=4 的那个（value=17），不是 value=4 的那个（key=1）
```

> unordered_map 底层哈希表是按 key 哈希的，所以查找也只能按 key 查。
>
> 如果想按 value 找，只能自己遍历整个 unordered_map 一个个比较，时间复杂度是 O(n)。

## 为什么不用 中括号 查找？

上节课讲过，`中括号` 有副作用——如果 key 不存在，它会自动插入一个（value 为默认值）。

```cpp
unordered_map<int, int> um = { {1, 10} };

// ❌ 错误做法：用 中括号 查找
// 如果 key=2 不存在，会被自动插入到 unordered_map 里
int val = um[2];   // 副作用：um 里多了一个 (2, 0)
```

所以**查找一定要用 find**，不要用 `中括号`。`中括号` 只适合明确要插入或修改的场景。

## 时间复杂度

`find` 的平均时间复杂度是 **O(1)**。

> 底层是哈希表，先通过哈希函数直接定位到 bucket，然后在桶内链表上比较。
> 如果哈希函数好、冲突少，基本一次就能找到，所以平均是 O(1)。
> 最坏情况（所有元素都哈希到同一个桶）是 O(n)，但实际中几乎不会遇到。

## 完整代码示例

```cpp
#include <iostream>
#include <unordered_map>
using namespace std;

int main() {
    unordered_map<int, int> um = {
        pair<int, int>(1, 4),
        pair<int, int>(2, 80),
        pair<int, int>(3, 20),
        pair<int, int>(4, 17)
    };

    // 循环检查 key=4 和 key=5
    for (int i = 4; i <= 5; ++i) {
        unordered_map<int, int>::iterator it = um.find(i);
        if (it != um.end()) {
            cout << "找到键值对：("
                 << it->first << ", "
                 << it->second << ")" << endl;
        } else {
            cout << "未找到 key=" << i << endl;
        }
    }

    return 0;
}
```

运行结果：

```
找到键值对：(4, 17)
未找到 key=5
```

## 本章小结

**find 按 key 查找** — 参数传 key，返回迭代器，和 value 没关系。

**判断方法** — `it != um.end()` 说明找到了，等于 end 说明没找到。

**找到才能访问** — 一定要先判断再 `it->first` 和 `it->second`，否则可能崩溃。

**查找不要用 中括号** — 中括号 有副作用，key 不存在时会自动插入。查找请用 find。

**时间复杂度平均 O(1)** — 哈希表查找效率比红黑树的 O(log n) 更高。

**和 map 的 find 几乎一模一样** — 只不过 map 底层是红黑树、unordered_map 底层是哈希表，接口用法完全一致。
