## 本节概述：list 的数据访问

学 vector 和 deque 的时候，我们可以用 `[]` 下标或者 `at()` 来随机访问元素。但到了 list 这里——**都不行了**。这节课我们来搞清楚为什么，以及 list 到底怎么访问元素。

## list 不支持随机访问

### 没有 [] 运算符

试试用下标访问：

```cpp
list<int> L = {-1, 9, 8, 5, 2, 1, 1, -1};
cout << L[4] << endl;   // ❌ 编译报错！
```

报错信息大概是：**没有与这些操作数匹配的 `[]` 运算符**。

### 没有 at 方法

再试试 `at()`：

```cpp
cout << L.at(4) << endl;  // ❌ 连 at 这个方法都没有！
```

> 没错，list 根本就没有提供 `at` 这个成员函数。

### 结论：list 无法随机访问

**`[]` 没有，`at()` 也没有**——list 不支持随机访问。

> [!WARNING]
> **为什么不提供？因为效率低**
>
> 链表的节点在内存里不是连续的，要找到第 n 个元素，必须从头节点开始一个一个往后数——时间复杂度 **O(n)**。
>
> 如果 STL 提供了 `[]` 运算符，你可能会随手写 `L[i]` 以为是 O(1) 的，
> 结果实际是 O(n) 的，写出来的代码奇慢无比，你还不知道为啥。
>
> 所以 STL 的设计思路是：**干脆不提供**，让你从根源上避免写出低效代码。
> 想随机访问？自己用循环 `++` 走过去，但你要清楚地知道"这是 O(n) 的"。

## 迭代器也不能跳着走

list 的迭代器只支持 `++` 和 `--`，**不支持 `+n` / `-n`**：

```cpp
list<int>::iterator it = L.begin();
++it;            // ✅ 可以，往前走一格
it++;            // ✅ 也可以
--it;            // ✅ 可以，往后退一格
it = it + 1;     // ❌ 编译报错！
it += 3;         // ❌ 也不行！
```

道理跟上面一样——跳 n 格就得走 n 次 `++`，O(n) 的效率。索性不让你用 `+`，避免你无意中写出低效代码。

> 想走 n 格？自己写 for 循环 `++` n 次。丑是丑了点，但你清楚地知道这是 O(n) 的。

## 怎么访问中间元素：自己封装

如果确实需要按下标访问，可以自己封装一个函数：

```cpp
int getListItemByIndex(list<int>& L, int index) {
    list<int>::iterator it = L.begin();
    while (index > 0) {
        ++it;
        --index;
    }
    return *it;
}
```

用的时候：

```cpp
list<int> L = {-1, 9, 8, 5, 2, 1, 1, -1};
cout << getListItemByIndex(L, 4) << endl;   // 2
```

> 下标从 0 开始数：0 是 -1，1 是 9，2 是 8，3 是 5，4 是 2。
> 传 4 返回 2，没错。

> [!NOTE]
> **但不推荐经常这么干**
>
> 每次访问都要从头数，时间复杂度 O(n)，访问 n 次就是 O(n²)。
> 如果你需要大量的随机访问操作，应该直接用 vector 或 deque，而不是 list。
>
> **链表的优势在插入删除，不在访问**——各有各的擅长领域。

## 能直接访问的只有头尾

list 直接提供访问的，只有头和尾两个位置：

```cpp
cout << L.front() << endl;   // -1（队首）
cout << L.back() << endl;    // -1（队尾）
```

这两个都是 O(1) 的——list 是双向链表，头尾各有一个指针，直接取就行。

| 接口 | 作用 | 时间复杂度 |
|---|---|---|
| `front()` | 取第一个元素 | O(1) |
| `back()` | 取最后一个元素 | O(1) |

## 为什么会这样？底层是双向链表

知道了 list 底层是**双向链表**，一切就都解释得通了：

- 节点在内存里**不连续** → 不能通过下标直接算地址 → 不支持 `[]` / `at`
- 想找第 n 个节点只能**一个一个往后走** → 时间复杂度 O(n) → STL 干脆不提供随机访问
- 头尾各有一个指针 → `front()` / `back()` 直接取 → O(1)

> 不理解底层结构，就会觉得"为什么这么难用"；理解了底层结构，就会觉得"设计得真合理"。

## 本章小结

**没有 `[]` 和 `at()`** — list 不支持下标访问，也没有 at 方法。

**原因：效率低** — 链表节点不连续，随机访问得从头数，O(n) 时间。STL 故意不提供，防止写出低效代码。

**迭代器只能 ++/--** — 不能 `+n` / `-n`，同样是为了避免无意中的 O(n) 操作。

**可以自己封装，但不推荐常用** — 用 for 循环 `++` 可以按下标访问，但每次都是 O(n)，频繁用会很慢。

**只能直接访问头尾** — `front()` 和 `back()` 都是 O(1) 的。

**底层决定一切** — 知道 list 是双向链表，就理解了为什么它的访问方式是这样的。
